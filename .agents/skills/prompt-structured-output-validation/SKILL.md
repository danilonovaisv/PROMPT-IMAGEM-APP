# Prompt Structured Output Validation

## Purpose

Enforce strict schema conformance and defensive parsing for multimodal cataloging outputs generated by `@google/genai` in `server/ai/`.

## Use When

- Updating or extending `server/ai/promptAnalyzer.ts`.
- Defining or changing `responseJsonSchema` or `Type` structures.
- Adding new fields to structured prompt metadata (camera, lighting, environment, tags).
- Handling model output parse errors, schema mismatches, or malformed JSON responses.

## Do Not Use When

- Altering client-side form validation in `src/features/`.
- Validating HTTP request bodies (use `server/validation/`).
- Making direct database schema modifications.

## Required Context

- `server/ai/gemini.ts`
- `server/ai/promptAnalyzer.ts`
- `src/types/index.ts` (StructuredPrompt, PromptItem)

## Procedure

1. **Schema Definition:** Use `Type.OBJECT`, `Type.STRING`, `Type.ARRAY` from `@google/genai`. Ensure all objects declare explicit `properties`.
2. **Deterministic Fallback:** If the Gemini API call fails, times out, or returns unparseable content, immediately trigger the heuristic fallback parser. Never throw unhandled 500 errors to the client.
3. **Draft Preservation:** Treat AI analysis strictly as a draft. Always preserve the original `rawPrompt` and reference image paths untouched.
4. **Validation Routine:** Validate the parsed JSON using TypeScript runtime type guards before constructing the `StructuredAnalysisResult`.

## Security & Privacy

- Never log raw API keys (`GEMINI_API_KEY`).
- Do not log complete prompt payloads or base64 image strings in production logs.
